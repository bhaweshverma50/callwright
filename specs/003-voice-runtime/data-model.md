# Data Model: Voice Runtime

**Feature**: 003-voice-runtime | **Date**: 2026-10-16 | **Plan**: [plan.md](./plan.md)

All tenant tables carry `workspace_id` with row-level security
`USING (workspace_id = current_setting('app.workspace_id'))`, following
research/architecture.md section 4. Timestamps are `timestamptz` (UTC). IDs are prefixed ULIDs
generated by `core.ids`. Migrations are forward-only, in `services/api/app/migrations/`.

### Call state machine

| From | To | Trigger | Writer |
|---|---|---|---|
| (new) | `queued` | admission succeeded | API `calls.service.admit` |
| (new) | `failed` | admission refused (`insufficient_credit`, `concurrency_limit`, `error`) | API |
| `queued` | `ringing` | outbound dial started, or inbound ring phase started | worker status event |
| `queued` | `in_progress` | web caller joined | worker status event |
| `ringing` | `in_progress` | answered (outbound) or ring duration elapsed (inbound) | worker status event |
| `ringing` | `no_answer` | ring timeout, SIP 408/480/487 | worker status event |
| `ringing` | `busy` | SIP 486/600 | worker status event |
| `queued`, `ringing` | `failed` | dial error, worker unavailable, caller never joined, inbound route refused | worker or reaper |
| `in_progress` | `ended` | any disconnect reason | worker status event, reaper or `room_finished` hook |
| `ended` | `processing` | pipeline started | API pipeline |
| `processing` | `completed` | pipeline finished | API pipeline |
| `processing` | `voicemail` | pipeline finished for a call with reason `voicemail_reached` | API pipeline |

Rules:
- Transitions are applied with `UPDATE ... WHERE id = :id AND status = :expected`; a stale
  transition is ignored and logged, never an error.
- `failed`, `no_answer`, `busy` are terminal and never run billing, analysis or evaluation; they
  enqueue only the `call_ended` webhook (spec FR-035).
- `disconnect_reason` is set exactly once, by the first writer to move the call to `ended`.
- `billable_seconds` is computed when `ended_at` is written.
- Recording setting: at admission `recording_enabled = (v.advanced.recording == 'on') OR
  (v.advanced.recording == 'inherit' AND workspaces.recording_default)`, where `v` is the frozen
  AgentConfig (002; a missing field reads as `inherit`) and `workspaces.recording_default` is
  owned by 001 (default true). Both columns are immutable after insert. When false: no egress is
  started, `egress_id` and `recording_key` stay null, `recording_status = not_recorded`, egress
  webhooks for the call are ignored, and transcript, `call_events`, `usage` and
  `latency_stats` are written exactly as for a recorded call. `not_recorded` is never a
  pipeline warning; `failed` (recording expected but missing) is shown as "recording
  unavailable".

## 2. `call_events` (module `call_events`)

Per-turn latency and runtime facts (constitution: per-turn latency events stored in Postgres).

| Column | Type | Null | Notes |
|---|---|---|---|
| id | bigint identity PK | no | internal only |
| workspace_id | text | no | RLS key, copied from call |
| call_id | text FK calls ON DELETE CASCADE | no | |
| seq | integer | no | worker-assigned, strictly increasing per call |
| type | enum `call_event_type` | no | `status`, `turn`, `transcript_item`, `usage`, `tool_call`, `flow_transition`, `dtmf`, `warning`, `error` |
| occurred_at | timestamptz | no | worker clock |
| offset_ms | integer | yes | ms since `connected_at` |
| turn_index | integer | yes | agent turn number, 0 = greeting |
| stt_final_ms | integer | yes | `turn` only |
| eou_delay_ms | integer | yes | `turn` only |
| llm_ttft_ms | integer | yes | `turn` only |
| tts_ttfb_ms | integer | yes | `turn` only |
| e2e_ms | integer | yes | `turn` only; greeting turn stores `greeting_ms` here with `turn_index = 0` |
| tool_ms | integer | yes | filled by 005 hook |
| interrupted | boolean | yes | `turn` only |
| payload | jsonb | no | type-specific body (contract `CallEvent`) |

**Constraints**: `UNIQUE (call_id, seq)`; insert with `ON CONFLICT DO NOTHING` (idempotent
retries). Heartbeats are not stored as rows; any events post updates `calls.last_heartbeat_at`.
**Indexes**: `(call_id, seq)`; `(workspace_id, occurred_at) WHERE type = 'turn'` for latency
analytics (006).

## 3. `call_pipeline_steps` (module `calls`)

| Column | Type | Notes |
|---|---|---|
| call_id | text FK calls | PK part |
| step | enum `pipeline_step` | PK part: `finalize_transcript`, `price_and_charge`, `analyze`, `evaluate`, `notify_analyzed`, `complete` |
| workspace_id | text | RLS |
| status | enum `step_status` | `pending`, `running`, `done`, `failed`, `skipped` |
| blocking | boolean | true for `finalize_transcript`, `price_and_charge`, `complete` |
| attempts | integer | default 0 |
| last_error | text | truncated to 2 KB |
| started_at, finished_at | timestamptz | |

Rows are created together when the pipeline starts. A step runs only if all earlier blocking
steps are `done`. `analyze` and `evaluate` become `skipped` when no handler is registered (until
007 ships) and `failed` after their retries; either way the chain continues.

## 4. Webhooks (module `webhooks_out`)

### `webhook_signing_secrets`

| Column | Type | Notes |

| Column | Type | Notes |
|---|---|---|
| id | text PK | `whd_` ULID (new prefix, see plan Complexity Tracking) |

| event | enum `webhook_event` | `call_started`, `call_ended`, `call_analyzed`, `ping` |

| status | enum `delivery_status` | `pending`, `delivering`, `succeeded`, `failed`, `blocked` |

## 5. Transcript item (JSON in `calls.transcript.items[]`)

| `type` | Fields |
|---|---|
| `message` | `role` (`user`, `agent`), `text`, `started_ms`, `ended_ms`, `turn_index`, `interrupted` (agent only), `confidence` (user only, 0..1), `source` (`voice`, `keypad`) |
| `tool_call` | `ref`, `name`, `arguments` (object), `at_ms` (from 005) |
| `tool_result` | `ref`, `name`, `output` (string, max 8 KB), `is_error`, `duration_ms` (from 005) |
| `flow_transition` | `from_node_id`, `to_node_id`, `label`, `at_ms` (from 004) |
| `system` | `event` (`voicemail_detected`, `silence_timeout`, `max_duration`, `credit_exhausted`, `vendor_error`), `detail`, `at_ms` |

Agent message text is the model output before pronunciation replacement, truncated to the
words actually played when interrupted.

## 6. Usage snapshot (JSON in `calls.usage`, contract `UsageSnapshot`)

```json
{
  "seq": 42,
  "stt": [{"provider": "deepgram", "model": "nova-3", "audio_ms": 271000}],
  "llm": [{"provider": "azure_openai", "model": "gpt-5.1", "input_tokens": 102348,
           "cached_input_tokens": 80000, "output_tokens": 745}],
  "tts": [{"provider": "elevenlabs", "model": "eleven_flash_v2_5", "characters": 2555}],
  "nc":  [{"provider": "sanas_vi", "audio_ms": 271000}]
}
```

Arrays allow more than one model per call (a flow node may override the model, 004).
Counters are cumulative and monotonically non-decreasing; the API rejects a snapshot whose
`seq` is lower than `usage_seq`.

## 7. Latency statistics (JSON in `calls.latency_stats`)

`{turns, greeting_ms, e2e_p50_ms, e2e_p95_ms, e2e_avg_ms, e2e_max_ms, stt_final_avg_ms,
eou_delay_avg_ms, llm_ttft_avg_ms, tts_ttfb_avg_ms}` computed from `call_events` rows of type
`turn` with `turn_index > 0`.

## 9. Worker-side runtime objects (not persisted by the worker)

- **RuntimeConfig** (claim response): `call_id`, `admitted`, `refusal_reason`, `channel`,
  `direction`, `from_number`, `to_number`, `agent_id`, `agent_version_id`, `config`
  (AgentConfig from 002), `variables`, `limits {end_on_silence_s, max_duration_s,
  ring_duration_ms}`, `features {voicemail, dtmf, background_audio, pronunciation}`,
  `recording_enabled` (informational; egress is started by the API, never by the worker),
  `background_audio_url`, `outbound_dial` (set by 010), `heartbeat_interval_s` (10).
- **TurnRecord**: `turn_index`, `user_end_of_speech_at`, `agent_first_audio_at`, component
  metrics, `interrupted`, `played_text`.
- **CallControl** state: `ending`, `disconnect_reason` (first writer wins), `pending_digits`.

## 10. Validation rules (from spec)

- Variable names `^[A-Za-z_][A-Za-z0-9_]{0,63}$`; max 50 entries; values max 2,000 chars; built-in
  names rejected silently and listed in `ignored_overrides` (FR-005, FR-006).
- `metadata` max 4 KB serialized, max 20 keys.
- `recording_status = not_recorded` if and only if `recording_enabled = false` (check constraint
  `calls_recording_consistency`).
- Webhook URL: absolute `https://` (or `http://` when `ENV=development`), host not resolving to
  blocked ranges at send time (FR-040).
- Limits read from the version: `end_on_silence_s` 10..300, `max_duration_s` 30..3,600,
  `webhook_timeout_ms` 1,000..30,000, `dtmf.timeout_ms` 1,000..10,000, `dtmf.digits` 1..99,
  voicemail message max 500 chars. Out-of-range values in a version are clamped and a warning
  event is recorded (002 validates on save; this is defence in depth).
